🎯 Yang akan Anda bangun

Saat ini toko online mengerjakan semuanya di dalam request checkout pelanggan, sehingga API kurir yang lambat berarti checkout yang lambat. Anda membangun bagian pertama dari desain yang lebih baik: sebuah function yang dipicu HTTP bernama new_order yang memvalidasi pesanan dan memasukkannya ke Storage queue melalui output binding, lalu langsung menjawab. Sisi gudang bisa memproses queue itu dengan kecepatannya sendiri. Function app berjalan di plan Flex Consumption (Python, bisa menyusut ke nol) dan menjangkau queue dengan managed identity miliknya, sehingga tidak ada storage key di koneksinya. Terakhir, sebuah Logic App Consumption mengirim pesanan "heartbeat" (detak jantung) setiap 15 menit untuk membuktikan bahwa alur pesanan masih berfungsi.

Southeast Asia, region default kursus ini, menyediakannya saat tulisan ini dibuat. Jika Anda memakai Indonesia Central atau region lain yang tidak ada di daftar, skrip akan berhenti dan menampilkan region yang menyediakannya; pilih salah satunya (misalnya export LOCATION=eastasia), jalankan source untuk kedua file itu lagi, lalu jalankan ulang setup.sh. Tugas 1Memeriksa titik awal dan kodenya

Serverless tidak berarti "tanpa resource": function app memerlukan storage account untuk pembukuannya sendiri, dan function kita memerlukan tempat untuk menaruh pesanan. Periksa apa saja yang dibuat oleh setup.sh, lalu baca kode yang akan Anda deploy.

bash
az resource list -g "$RG" --query "[].{name:name, type:type}" --output table
az storage queue exists --name "$QUEUE" --account-name "$ST" --auth-mode key --only-show-errors --output tsv
cat function/function_app.py
cat function/host.json

Di function_app.py, perhatikan tiga decorator pada new_order: @app.function_name memberi nama fungsi, @app.route menjadikannya HTTP trigger untuk POST /api/orders, dan @app.queue_output(..., connection="OrdersStorage") adalah output binding-nya. Sementara itu, http_auth_level=FUNCTION yang berlaku untuk seluruh aplikasi berarti pemanggil memerlukan function key. Kode hanya memanggil msg.set(...); host Functions-lah yang menulis pesan ke queue. host.json mengunci extension bundle (kumpulan extension untuk binding) ke versi 4 dan mengatur messageEncoding ke none, sehingga pesan di queue berupa JSON biasa yang bisa Anda baca.

✅ Pemeriksaan: tabel menampilkan sebuah storage account dan sebuah workspace Log Analytics, dan perintah kedua mencetak True.

Tugas 2Membuat function app di Flex Consumption

Satu perintah membuat function app, plan Flex Consumption-nya (satu aplikasi per plan), dan sebuah resource Application Insights yang menyimpan datanya di workspace Anda. Prosesnya memakan waktu satu atau dua menit.

bash
az functionapp create \
  --resource-group "$RG" \
  --name "$FUNC" \
  --storage-account "$ST" \
  --flexconsumption-location "$LOCATION" \
  --runtime python --runtime-version "$PY_VERSION" \
  --functions-version 4 \
  --instance-memory 2048 \
  --maximum-instance-count 10 \
  --workspace "$LAW" \
  --https-only true \
  --output none

--instance-memory 2048 memilih ukuran instance default (pilihan lainnya adalah 512 MB dan 4.096 MB). --maximum-instance-count 10 membatasi seberapa jauh aplikasi bisa scale out, yang melindungi anggaran Anda dan semua sistem di hilirnya. Tidak ada always-ready instance, jadi aplikasi menyusut ke nol saat menganggur dan Anda hanya membayar selama ia berjalan.

Lihat pengaturan yang ditulis oleh CLI:

bash
az functionapp config appsettings list -g "$RG" -n "$FUNC" --query "[].name" --output tsv

AzureWebJobsStorage dan DEPLOYMENT_STORAGE_CONNECTION_STRING menghubungkan host ke storage account-nya dengan connection string; itulah default dari CLI, dan cukup baik untuk lab. APPLICATIONINSIGHTS_CONNECTION_STRING mengirim telemetri. Aplikasi production juga mengalihkan storage untuk host ke managed identity (lihat Pelajari lebih lanjut di bacaan).

TipsLebih suka portal? Create a resource › Function App › Flex Consumption: runtime Python 3.12, region Anda, instance size 2048 MB; di tab Storage pilih stnusaorders<suffix>; di tab Monitoring aktifkan Application Insights dengan workspace log-nusa. Tab Authentication bisa mengalihkan semua koneksi ke managed identity sekaligus.

✅ Pemeriksaan: az functionapp plan list -g "$RG" --query "[].{plan:name, sku:sku.name, tier:sku.tier}" --output table menampilkan satu plan dengan SKU FC1 (Flex Consumption), dan az functionapp show -g "$RG" -n "$FUNC" --query state --output tsv mencetak Running.

Tugas 3Memberi function koneksi tanpa kata sandi ke queue

Kode meminta sebuah koneksi bernama OrdersStorage. Alih-alih menempelkan storage key ke sebuah pengaturan, Anda memberi function app managed identity-nya sendiri, mengizinkan identitas itu menulis pesan ke queue, lalu memberi tahu host di mana layanan queue berada. Tiga langkah:

bash
# 1. A system-assigned managed identity for the function app
PRINCIPAL_ID=$(az functionapp identity assign -g "$RG" -n "$FUNC" --query principalId --output tsv)

# 2. Permission to send messages to queues in this storage account (data-plane role)
ST_ID=$(az storage account show -g "$RG" -n "$ST" --query id --output tsv)
az role assignment create \
  --assignee-object-id "$PRINCIPAL_ID" \
  --assignee-principal-type ServicePrincipal \
  --role "Storage Queue Data Contributor" \
  --scope "$ST_ID" \
  --output none

# 3. The connection: <name>__queueServiceUri tells the host "use an identity for this queue service"
QUEUE_URI=$(az storage account show -g "$RG" -n "$ST" --query primaryEndpoints.queue --output tsv)
az functionapp config appsettings set -g "$RG" -n "$FUNC" \
  --settings "OrdersStorage__queueServiceUri=${QUEUE_URI%/}" --output none

Garis bawah ganda itu penting: setiap pengaturan yang diawali OrdersStorage__ adalah bagian dari koneksi OrdersStorage. Karena pengaturan itu hanya berisi alamat dan tanpa secret, kebocorannya tidak memberi akses kepada siapa pun. Role assignment yang baru bisa memerlukan beberapa menit sampai berlaku; Tugas 4 memberinya waktu itu.

✅ Pemeriksaan: az role assignment list --assignee "$PRINCIPAL_ID" --scope "$ST_ID" --query "[].roleDefinitionName" --output tsv mencetak Storage Queue Data Contributor, dan az functionapp config appsettings list -g "$RG" -n "$FUNC" --query "[?starts_with(name, 'OrdersStorage')].name" --output tsv mencetak OrdersStorage__queueServiceUri.

Tugas 4Men-deploy kode

Aplikasi Flex Consumption berjalan dari paket zip di sebuah blob container. Untuk Python, selalu minta remote build, agar dependensinya dipasang di Linux di Azure, bukan di mesin Anda. Perkirakan waktunya 1–3 menit.

bash
mkdir -p "$OUT_DIR"
(cd function && python3 -m zipfile -c "$OUT_DIR/function.zip" function_app.py host.json requirements.txt)
az functionapp deployment source config-zip -g "$RG" -n "$FUNC" \
  --src "$OUT_DIR/function.zip" --build-remote true

TipsLebih suka alat lain? Azure Functions Core Tools (func azure functionapp publish <app>) dan extension Azure Functions di VS Code men-deploy paket yang sama; GitHub Actions melakukannya pada setiap push.

✅ Pemeriksaan: az functionapp function list -g "$RG" -n "$FUNC" --query "[].name" --output tsv mencetak sebuah nama yang berakhiran /new_order. Jika hasilnya kosong, tunggu 30 detik lalu coba lagi.

Tugas 5Mengirim pesanan dengan curl dan mengintip queue

Baca URL dan key function dari Azure, lalu buat pesanan seperti yang akan dilakukan toko online:

bash
ORDER_URL=$(az functionapp function show -g "$RG" -n "$FUNC" --function-name new_order --query invokeUrlTemplate --output tsv)
FUNC_KEY=$(az functionapp function keys list -g "$RG" -n "$FUNC" --function-name new_order --query default --output tsv)
echo "$ORDER_URL"

curl -s -w '\nHTTP %{http_code}\n' -X POST "$ORDER_URL" \
  -H "x-functions-key: $FUNC_KEY" -H "Content-Type: application/json" \
  -d '{"orderId":"JKT-1001","store":"Jakarta - Kemang","items":[{"sku":"KOPI-TORAJA-250G","qty":2},{"sku":"SAMBAL-MATAH-200ML","qty":1}]}'

Anda mendapat {"status": "queued", ...} dan HTTP 200. Panggilan pertama setelah masa sepi bisa memakan beberapa detik: itulah cold start, saat platform menyalakan sebuah instance dari nol. Sekarang coba dua panggilan yang salah:

bash
curl -s -w '\nHTTP %{http_code}\n' -X POST "$ORDER_URL" -H "x-functions-key: $FUNC_KEY" \
  -H "Content-Type: application/json" -d '{"orderId":"JKT-1002"}'                    # 400 with the reasons
curl -s -o /dev/null -w 'HTTP %{http_code}\n' -X POST "$ORDER_URL" -d '{}'           # 401: no function key

Terakhir, intip isi queue. Mengintip (peek) membaca pesan tanpa menghapusnya:

bash
az storage message peek --queue-name "$QUEUE" --account-name "$ST" --auth-mode key \
  --num-messages 5 --only-show-errors --query "[].content" --output tsv

CatatanMendapat HTTP 500 di beberapa menit pertama? Role assignment dari Tugas 3 kemungkinan besar belum berlaku. Tunggu satu menit lalu kirim pesanan itu lagi.

✅ Pemeriksaan: hasil peek menampilkan pesan JSON dengan "orderId": "JKT-1001", waktu receivedAtUtc, dan sebuah trackingId. Pesanan yang ditolak tidak ada di queue.

Tugas 6Menjadwalkan pesanan heartbeat dengan Logic App

Ibu Sari ingin bukti setiap seperempat jam bahwa alur pesanan masih hidup. Itu pekerjaan untuk sebuah workflow, bukan untuk kode tambahan. Buka definisinya di logicapp/workflow.json: sebuah trigger Recurrence (setiap 15 menit) dan satu action HTTP yang mengirim pesanan heartbeat dengan function key di header x-functions-key. URL dan key-nya tertulis sebagai __ORDER_URL__ dan __FUNCTION_KEY__ di file itu; isilah di luar repository, karena hasilnya berisi secret:

bash
cat logicapp/workflow.json
sed -e "s|__ORDER_URL__|${ORDER_URL}|" -e "s|__FUNCTION_KEY__|${FUNC_KEY}|" \
  logicapp/workflow.json > "$OUT_DIR/workflow.json"
chmod 600 "$OUT_DIR/workflow.json"

az logic workflow create -g "$RG" -n "$LOGIC" -l "$LOCATION" \
  --definition "$OUT_DIR/workflow.json" --output none
az logic workflow show -g "$RG" -n "$LOGIC" --query state --output tsv

Run terjadwal yang pertama bisa baru terjadi hingga 15 menit lagi, jadi mulai satu run sekarang dan baca run history-nya melalui REST API Logic Apps:

bash
LOGIC_ID=$(az logic workflow show -g "$RG" -n "$LOGIC" --query id --output tsv)
az rest --method post --url "https://management.azure.com${LOGIC_ID}/triggers/Every_15_minutes/run?api-version=2016-06-01"
sleep 20
az rest --method get --url "https://management.azure.com${LOGIC_ID}/runs?api-version=2016-06-01" \
  --query "value[:3].{started:properties.startTime, status:properties.status}" --output table

TipsLebih suka portal? Buka logic-nusa-orders › Development Tools › Logic app designer untuk melihat trigger dan action yang sama dalam bentuk kotak-kotak; Code view menampilkan JSON-nya. Overview › Run trigger › Run memulai sebuah run, dan setiap entri di Run history menampilkan input, output, dan durasi setiap langkah. Anda juga bisa membangun seluruh workflow di designer: Recurrence (15 menit), lalu HTTP (POST, URL, kedua header, dan body JSON).

CatatanExtension az logic ditandai experimental oleh Microsoft. Jika az logic workflow create berperilaku aneh, buat workflow-nya di designer portal seperti dijelaskan di tip tadi; verify.sh tidak peduli bagaimana Anda membangunnya.

✅ Pemeriksaan: statusnya Enabled, run terbaru menunjukkan Succeeded, dan mengintip queue (Tugas 5) menampilkan sebuah pesan yang orderId-nya diawali HB-.

🔧 Rusak lalu perbaiki

Seorang rekan kerja merapikan pengaturan yang "tidak terpakai" di function app dan menghapus pengaturan dengan garis bawah ganda yang tampak aneh itu:

bash
az functionapp config appsettings delete -g "$RG" -n "$FUNC" --setting-names OrdersStorage__queueServiceUri --output none
sleep 60                                                     # the app restarts after a settings change
curl -s -w '\nHTTP %{http_code}\n' -X POST "$ORDER_URL" -H "x-functions-key: $FUNC_KEY" \
  -H "Content-Type: application/json" -d '{"orderId":"JKT-2001","store":"Jakarta - Kemang","items":[{"sku":"KOPI-TORAJA-250G","qty":1}]}'

Gejala: pesanan tidak lagi diterima. Tergantung kapan host menyadarinya, Anda mendapat HTTP 404 (host menolak memuat new_order karena binding-nya tidak punya koneksi, sehingga route-nya hilang) atau HTTP 500 (function berjalan, tetapi binding tidak bisa menjangkau queue). Run Logic App terjadwal berikutnya juga gagal. Temukan buktinya sebelum memperbaiki apa pun:

  1. Bandingkan konfigurasi dengan apa yang diharapkan oleh kode: az functionapp config appsettings list -g "$RG" -n "$FUNC" --query "[?starts_with(name, 'OrdersStorage')]" --output table

  2. Baca penjelasan dari host itu sendiri. Di portal, buka resource Application Insights func-nusa-<suffix> › Monitoring › Logs lalu jalankan query ini (entri log baru bisa butuh 2–5 menit untuk muncul):

    KQL
    traces
| where timestamp > ago(30m)
| where severityLevel >= 3 or message has "OrdersStorage"
| project timestamp, severityLevel, message
| order by timestamp desc
Petunjuk dan perbaikan

Log menyebut koneksi OrdersStorage dan mengatakan bahwa pengaturan untuk koneksi itu tidak ada. Binding masih meminta connection="OrdersStorage", tetapi tidak ada satu pun bagian konfigurasi yang mendefinisikannya. Kembalikan pengaturannya:

bash
QUEUE_URI=$(az storage account show -g "$RG" -n "$ST" --query primaryEndpoints.queue --output tsv)
az functionapp config appsettings set -g "$RG" -n "$FUNC" \
  --settings "OrdersStorage__queueServiceUri=${QUEUE_URI%/}" --output none

Setelah sekitar satu menit, curl yang sama mengembalikan HTTP 200, dan run Logic App berikutnya berhasil. Pelajarannya: pengaturan adalah bagian dari aplikasi. Beri nama yang jelas, simpan dalam kode (Makan Siang 20), dan pantau request yang gagal (Makan Siang 16).

🚀 Tantangan tambahan

  • Saksikan penskalaannya. Buka function app › Monitoring › Application Insights › Live metrics (atau Investigate › Live metrics di resource Application Insights), lalu kirim 200 pesanan dari Cloud Shell:

    bash
    seq 1 200 | xargs -P 20 -I{} curl -s -o /dev/null -X POST "$ORDER_URL" -H "x-functions-key: $FUNC_KEY" \
  -H "Content-Type: application/json" -d '{"orderId":"LOAD-{}","store":"Load test","items":[{"sku":"TEST","qty":1}]}'

    Perhatikan jumlah server dan request rate, lalu saksikan aplikasi kembali sepi.

  • Tambahkan consumer-nya. Tambahkan function yang dipicu queue ke function_app.py yang membaca setiap pesanan dan mencatatnya ke log, memakai @app.queue_trigger(arg_name="msg", queue_name="orders", connection="OrdersStorage") dan parameter msg: func.QueueMessage. Deploy ulang (Tugas 4) dan saksikan queue terkuras. Perhatikan bahwa verify.sh mengharapkan setidaknya satu pesan di queue, jadi jalankan verify.sh sebelum mencoba tantangan ini.

  • Singkirkan secret terakhir. Alihkan AzureWebJobsStorage dan storage untuk deployment ke managed identity (tab Authentication pada aplikasi Flex Consumption baru di portal menampilkan pengaturan tujuannya), dan lindungi function dengan autentikasi Microsoft Entra, bukan key (Makan Siang 15 dan Makan Siang 22).

  • Bangun ulang workflow di designer lalu bandingkan Code view-nya dengan logicapp/workflow.json.

🏁 Ringkasan tantangan

Bangun hal-hal berikut dengan cara apa pun yang Anda suka (portal, CLI, Bicep):

  1. Resource group rg-lunch14-<suffix> di region yang menyediakan plan Flex Consumption.
  2. Storage account stnusaorders<suffix> dengan queue bernama orders.
  3. Function app func-nusa-<suffix> di plan Flex Consumption, Python 3.12, yang menjalankan kode di function/. POST /api/orders dengan pesanan yang valid dan function key mengembalikan HTTP 200.
  4. Koneksi OrdersStorage yang didefinisikan di app settings, sebaiknya berbasis identitas (OrdersStorage__queueServiceUri ditambah role data queue untuk managed identity milik aplikasi).
  5. Setidaknya satu pesan pesanan di queue orders.
  6. Logic App Consumption logic-nusa-orders berstatus Enabled yang mengirim pesanan ke function sesuai jadwal.

Lalu jalankan bash verify.sh. Buntu? Intip solution.sh atau beralih ke mode Terpandu.
