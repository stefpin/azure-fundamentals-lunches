Tugas 1Region, geografi, dan pasangan

Setiap region termasuk dalam sebuah geografi (batas residensi data, yaitu batas wilayah tempat data boleh disimpan), dan sebagian region punya region pasangan. CLI menampilkan persis apa yang bisa dilihat subscription Anda, jadi mulailah dari sana.

bash
# How many physical regions can your subscription see?
az account list-locations --query "length([?metadata.regionType=='Physical'])"

# The regions closest to Nusantara Retail: geography, city and paired region
az account list-locations \
  --query "[?contains(['indonesiacentral','southeastasia','eastasia','malaysiawest'], name)].{region:name, geography:metadata.geography, city:metadata.physicalLocation, pair:metadata.pairedRegion[0].name}" \
  --output table

# Which physical regions have no paired region at all?
az account list-locations \
  --query "[?metadata.regionType=='Physical' && !metadata.pairedRegion].displayName" \
  --output tsv | sort

Perintah pertama hanya menghitung region fisik. Daftarnya juga memuat entri logis seperti "Asia Pacific", yang mengelompokkan region untuk sebagian layanan dan bukan tempat Anda men-deploy sesuatu.

TipsLebih suka portal? Buka dropdown region di halaman Create mana pun (misalnya Create a resource group): region dikelompokkan per geografi, seperti "(Asia Pacific) Southeast Asia". Pasangan dan jumlah zona lebih mudah dibaca di daftar region Azure milik Microsoft.

✅ Pemeriksaan: tabel menampilkan eastasia sebagai pasangan southeastasia (dan sebaliknya), sementara indonesiacentral dan malaysiawest menampilkan kolom pair yang kosong. Indonesia Central muncul di daftar "tanpa pasangan". Kolom geografi menampilkan region Singapura dan Hong Kong dalam satu geografi dan Jakarta di geografi lain (kata-kata persisnya berasal dari platform dan bisa sedikit berbeda dari dokumentasi).

Tugas 2Melihat ke dalam region Anda: zona, pemetaan zona, dan apa saja yang tersedia

Zona diberi nomor 1, 2, dan 3 di setiap subscription, tetapi nomor itu bersifat logis. Setiap subscription punya pemetaannya sendiri ke zona fisik, dan Anda bisa membaca milik Anda.

bash
# Your subscription's logical-to-physical zone mapping for LOCATION
az account list-locations \
  --query "[?name=='${LOCATION}'].availabilityZoneMappings | [0]" \
  --output table

# How many regions offer zones to your subscription?
az account list-locations --query "length([?availabilityZoneMappings])"

Berikutnya, periksa ukuran VM mana yang bisa di-deploy subscription Anda ke dalam zona. Daftar SKU-nya besar, jadi perintah ini bisa memakan waktu satu atau dua menit; bacalah paragraf berikutnya sambil menunggu.

bash
az vm list-skus --location "$LOCATION" --resource-type virtualMachines \
  --size Standard_B --zone --output table

--zone hanya menyisakan ukuran yang mendukung availability zone, dan kolom Zones menunjukkan di zona mana saja setiap ukuran ditawarkan. Secara bawaan, daftar ini menyembunyikan ukuran yang dibatasi untuk subscription Anda; tambahkan --all untuk ikut melihatnya, lengkap dengan alasannya di kolom Restrictions.

Terakhir, tanyakan kepada Azure Resource Manager apakah sebuah layanan tersedia di suatu region. Setiap resource provider (layanan Azure di balik sekelompok tipe resource) menerbitkan lokasi untuk setiap tipe resource-nya:

bash
for rt in Microsoft.Network/natGateways Microsoft.App/managedEnvironments; do
  ns="${rt%%/*}"; type="${rt#*/}"
  echo "== ${rt}"
  az provider show --namespace "$ns" \
    --query "resourceTypes[?resourceType=='${type}'].locations | [0]" --output tsv \
    | grep -i -E "indonesia|southeast asia|east asia" || echo "   (not listed in these regions)"
done

TipsLebih suka portal? Halaman publik produk yang tersedia per region menjawab pertanyaan yang sama untuk setiap produk. CLI lebih cocok untuk tipe resource yang persis, ukuran VM, dan batasan khusus subscription Anda sendiri.

✅ Pemeriksaan: tabel pemetaan menampilkan tiga baris (zona logis 1, 2, dan 3, masing-masing dengan nama zona fisik seperti southeastasia-az2); zona logis 1 Anda belum tentu zona fisik 1. Tabel SKU menampilkan beberapa ukuran seri B dengan 1,2,3 di kolom Zones. Perulangan (loop) mencetak nama region tempat setiap tipe resource tersedia.

Tugas 3Public IP zonal, zone-redundant, dan "tanpa zona"

Public IP adalah objek uji yang sempurna: dibuat dalam hitungan detik, biayanya sangat kecil, dan pengaturan zonanya terlihat jelas. Buat resource group dan tiga alamat Standard public IPv4.

bash
ensure_rg "$RG" 03

# Zonal: pinned to logical zone 1
az network public-ip create --resource-group "$RG" --name pip-nusa-zonal \
  --location "$LOCATION" --sku Standard --version IPv4 --allocation-method Static \
  --zone 1 --output none

# Zone-redundant: spread across zones 1, 2 and 3
az network public-ip create --resource-group "$RG" --name pip-nusa-zr \
  --location "$LOCATION" --sku Standard --version IPv4 --allocation-method Static \
  --zone 1 2 3 --output none

# No zone given: what does Azure do?
az network public-ip create --resource-group "$RG" --name pip-nusa-nozone \
  --location "$LOCATION" --sku Standard --version IPv4 --allocation-method Static \
  --output none

Sekarang bandingkan ketiganya:

bash
az network public-ip list --resource-group "$RG" \
  --query "[].{name:name, sku:sku.name, allocation:publicIPAllocationMethod, zones:join(', ', zones || \`[]\`)}" \
  --output table

Cara membaca hasilnya:

  • pip-nusa-zonal menampilkan 1. IP ini zonal: tinggal di zona 1 dan berbagi nasib dengan zona itu.
  • pip-nusa-zr menampilkan 1, 2, 3. IP ini zone-redundant: tetap bertahan saat zona mana pun hilang.
  • pip-nusa-nozone kemungkinan besar menampilkan kolom zones yang kosong. Jangan artikan itu sebagai "nonzonal". Di region yang punya availability zone, Microsoft memperlakukan Standard public IP tanpa pengaturan zona sebagai zone-redundant; IP yang tidak menampilkan zona berperilaku sama dengan IP yang menampilkan 1, 2, 3. Hanya di region tanpa zona sebuah public IP benar-benar nonzonal. Tergantung versi API-nya, kolom itu juga mungkin kembali dalam keadaan terisi. Apa pun hasilnya, tetapkan --zone secara eksplisit di script Anda agar niat Anda jelas bagi pembaca berikutnya.

Satu aturan lagi: pengaturan zona sebuah public IP ditetapkan saat IP itu dibuat. Untuk mengubahnya, Anda harus membuat IP baru, yang berarti juga alamat baru, jadi putuskan dulu sebelum Anda memberikan alamat itu kepada mitra atau memasukkannya ke record DNS.

TipsLebih suka portal? Home › Public IP addresses › Create: perhatikan pengaturan Availability zone dan pilihan yang ditawarkannya di region Anda, lalu tinggalkan halaman itu tanpa membuat apa pun.

✅ Pemeriksaan: tiga IP Standard dengan alokasi Static ada di rg-lunch03-<suffix>, dengan zona 1, 1, 2, 3, dan (kemungkinan besar) kosong.

Tugas 4Storage LRS versus ZRS

Storage account menampilkan pilihan yang sama dalam bentuk redundansi. Locally redundant storage (LRS) menyimpan tiga salinan di satu pusat data; zone-redundant storage (ZRS) menyimpan salinan di tiga zona dan baru mengonfirmasi penulisan setelah setiap salinan menerimanya. Buat satu dari masing-masing jenis, keduanya dengan TLS 1.2 sebagai versi minimum dan akses blob anonim dimatikan.

bash
az storage account create --name "$ST_LRS" --resource-group "$RG" --location "$LOCATION" \
  --sku Standard_LRS --kind StorageV2 --min-tls-version TLS1_2 --allow-blob-public-access false \
  --output none

az storage account create --name "$ST_ZRS" --resource-group "$RG" --location "$LOCATION" \
  --sku Standard_ZRS --kind StorageV2 --min-tls-version TLS1_2 --allow-blob-public-access false \
  --output none

Bandingkan keduanya:

bash
az storage account list --resource-group "$RG" \
  --query "[].{name:name, sku:sku.name, primary:primaryLocation, secondary:secondaryLocation, status:statusOfPrimary}" \
  --output table

Kedua account tinggal di LOCATION Anda, dan kolom secondary kosong untuk keduanya: LRS dan ZRS tidak pernah keluar dari region. ZRS melindungi Anda dari kehilangan satu pusat data atau satu zona utuh; ZRS tidak melindungi Anda dari kehilangan region, dan, seperti setiap opsi redundansi, ZRS juga ikut menyalin penghapusan dan penimpaan. Lokasi sekunder hanya muncul pada opsi geo-redundant (GRS, GZRS), yang mereplikasi ke region pasangan. Tantangan tambahan di akhir lab memberi Anda kesempatan untuk melihatnya.

TipsLebih suka portal? Home › Storage accounts › Create: dropdown Redundancy di tab Basics menawarkan pilihan yang sama. Bandingkan apa yang ditawarkannya di Southeast Asia dan di Indonesia Central.

✅ Pemeriksaan: dua account StorageV2, stnusalrs<suffix> dengan Standard_LRS dan stnusazrs<suffix> dengan Standard_ZRS, keduanya dengan LOCATION Anda sebagai lokasi primer dan tanpa lokasi sekunder.

Tugas 5 (opsional)Pemeriksaan latensi kasar dari browser Anda

Cloud Shell berjalan di dalam pusat data Azure, jadi ia tidak bisa memberi tahu apa yang dirasakan para pembeli Anda. Browser Anda sendiri bisa.

  1. Buka halaman Azure Latency Test buatan komunitas (alat gratis dari pihak ketiga, bukan layanan Microsoft).
  2. Pilih Indonesia Central, Southeast Asia, East Asia, dan Malaysia West, lalu biarkan berjalan selama satu menit.
  3. Catat waktu bolak-balik (round trip) median untuk setiap region, lalu bandingkan.

Anggap angka-angka itu sebagai sinyal kasar: pengujian berjalan lewat HTTPS dari browser Anda, jadi waktu pencarian DNS dan handshake TLS ikut terhitung, dan hasilnya bergantung pada penyedia internet Anda sendiri. Untuk angka antar-region yang diukur di dalam jaringan Microsoft, gunakan statistik latensi antar-region dari Microsoft.

✅ Pemeriksaan: Anda punya empat angka latensi. Dari sebagian besar tempat di Indonesia, Jakarta biasanya diharapkan menjadi yang tercepat, tetapi jaringan Anda yang punya keputusan akhir. Justru karena itulah Anda mengukurnya.

🔧 Rusak lalu perbaiki

Zone-redundant storage membutuhkan region yang punya availability zone. Cobalah membuat account ZRS di region yang sama sekali tidak punya zona.

bash
# Find a physical region without availability zones (falls back to westus, which has none)
NOZONE_REGION=$(az account list-locations \
  --query "[?metadata.regionType=='Physical' && metadata.regionCategory=='Recommended' && !availabilityZoneMappings].name | [0]" \
  --output tsv)
NOZONE_REGION=${NOZONE_REGION:-westus}
echo "Region without zones: ${NOZONE_REGION}"

az storage account create --name "stnusabrk${SUFFIX}" --resource-group "$RG" \
  --location "$NOZONE_REGION" --sku Standard_ZRS --kind StorageV2 --output none

Gejala: perintah gagal dengan error yang menyatakan bahwa SKU Standard_ZRS tidak didukung atau tidak tersedia di lokasi itu. (Jika error-nya justru menyatakan bahwa lokasi itu tidak tersedia untuk subscription Anda, pilih region lain dari daftar dan coba lagi.)

Petunjuk dan perbaikan

ZRS menyebarkan salinan ke beberapa availability zone, jadi ZRS hanya ada di region yang memiliki zona. Sebelum memilih opsi redundansi, periksa region-nya:

bash
az account list-locations --query "[?name=='${NOZONE_REGION}'].availabilityZoneMappings | [0]" --output table

Hasil kosong berarti tidak ada zona. Perbaiki dengan memilih region yang punya zona (--location "$LOCATION") atau, jika Anda benar-benar membutuhkan region itu, dengan memakai Standard_LRS dan menerima bahwa kegagalan satu pusat data akan membuat data tidak bisa diakses. Lalu pastikan tidak ada resource tambahan yang telanjur terbuat:

bash
if az storage account show --name "stnusabrk${SUFFIX}" --resource-group "$RG" --output none 2>/dev/null; then
  az storage account delete --name "stnusabrk${SUFFIX}" --resource-group "$RG" --yes
else
  echo "Nothing to remove: the failed request created nothing."
fi

🚀 Tantangan tambahan

  • Buat account geo-redundant (--sku Standard_GRS) di Southeast Asia, jalankan query perbandingan dari Tugas 4, dan lihat kolom secondary: kolom itu menyebutkan region pasangannya. Hapus account itu setelahnya.
  • Coba perintah Standard_GRS yang sama dengan --location indonesiacentral. Apa yang terjadi, dan mengapa? (Petunjuk: GRS mereplikasi ke region pasangan.)
  • Hitung harga 100 GB storage LRS, ZRS, dan GRS di pricing calculator untuk Southeast Asia dan Indonesia Central, lalu catat perbedaannya antar-region dan antar-opsi redundansi.
  • Jika Anda punya akses ke subscription kedua, bandingkan pemetaan zona logis ke zona fisiknya dengan milik Anda.

🏁 Ringkasan tantangan

Bangun hal-hal berikut dengan cara apa pun yang Anda suka (portal, CLI, Bicep), di region yang punya availability zone:

  1. Resource group rg-lunch03-<suffix> di LOCATION Anda, dengan tag course=azure-fundamentals-lunches dan lunch=03 (ensure_rg melakukannya untuk Anda).
  2. Alamat public IPv4 Standard yang statis, pip-nusa-zonal, yang dipatok hanya ke zona 1.
  3. Alamat public IPv4 Standard yang statis, pip-nusa-zr, yang secara eksplisit zone-redundant di zona 1, 2, dan 3.
  4. Dua account StorageV2, stnusalrs<suffix> dengan Standard_LRS dan stnusazrs<suffix> dengan Standard_ZRS, keduanya dengan TLS 1.2 sebagai versi minimum dan akses blob anonim dinonaktifkan.
  5. Tidak diperiksa oleh script: catat geografi region Anda, region pasangannya (jika ada), dan pemetaan zona logis ke zona fisik di subscription Anda.
