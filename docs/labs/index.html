How the labs work

  • Independent. No lab needs another lab. When a lab needs a starting point (for example two web servers for the load balancing lab), its setup.sh creates it.

  • Azure Cloud Shell (Bash) is all you need: open shell.azure.com, choose Bash, then:

    bash
    git clone https://github.com/stefpin/azure-fundamentals-lunches.git   # first time only
cd azure-fundamentals-lunches
bash labs/common/check-environment.sh                                               # checks region, VM sizes, quota

  • Two modes. Guided walks you through each task with checkpoints. Challenge gives you only the requirements.

  • Scripts in every lab folder:

    Script What it does
    setup.sh creates the starting point (only in labs that need one)
    solution.sh the reference solution (in labs whose tasks can be scripted)
    verify.sh checks your work and prints PASS or FAIL for each requirement
    cleanup.sh deletes everything the lab created

  • Shared settings live in common/config.sh: region (LOCATION, default southeastasia), a second region for multi-region labs (SECONDARY_LOCATION, default eastasia), small VM sizes, and a random suffix that keeps globally unique names unique. Override them before you start, for example:

    bash
    export LOCATION=indonesiacentral        # Jakarta — check that each lab's services are offered there
source labs/common/config.sh

Cost bands

Band Meaning What to do
💲 free or close to free (uses free tiers or tiny resources) clean up anyway — good habit
💲💲 small charges while resources run, typically cents per hour finish the lab in one sitting, then run cleanup.sh
💲💲💲 noticeable charges while running, or gateways that take long to create plan the lab, then delete immediately afterwards

Prices vary by region and change over time, so the labs do not quote them. Use the Azure pricing calculator when you want numbers, and set the budget from Lab 01 before anything else.

WarningNever run the labs in a company or production subscription. Several labs create users, role assignments, policies or management groups, which affect everything in that scope.

When something goes wrong

  1. Read the error message — most failures are a region that does not offer a VM size, a quota limit, or a name that is already taken. bash labs/common/check-environment.sh checks the first two.
  2. Check the lab's Troubleshooting table.
  3. Still stuck? Report a lab problem with the lab number, the command and the full error.
